Spring Boot Project - Learning Notes

A User Management REST API with Spring Boot 3.5, JPA, PostgreSQL & Security

What does this project do?

This is a User Management API that lets you Create, Read, Update, and Delete (CRUD) users. It stores data in a PostgreSQL database and has basic security configured.

Tech Stack:

Spring Boot 3.5 Spring Data JPA PostgreSQL Spring Security Lombok JWT (jjwt)

Lombok is configured as an annotation processor in the Maven compiler plugin (lines 94-130 of pom.xml). This means Lombok runs at compile time and generates the getter/setter/builder bytecode into your .class files.

Architecture - Layered Design

This project follows the standard 3-tier layered architecture:

HTTP Request comes here first Controller Layer (UserController)
Business logic lives here Service Layer (UserService)
Database queries generated here Repository Layer (UserRepository)
Actual data stored here PostgreSQL Database (users table)

Why layered?

  • Separation of concerns: Each layer has one job
  • Testability: You can test service layer without HTTP
  • Maintainability: Change DB without touching controller
  • Reusability: Same service can be used by multiple controllers

Model Layer - User Entity

User.java - The Entity

@Entity
@Table(name = "users")
@Getter @Setter @NoArgsConstructor @AllArgsConstructor @Builder
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, unique = true)
    private String username;

    @Column(nullable = false)
    private String password;

    @Column(nullable = false, unique = true)
    private String email;

    private String firstName;
    private String lastName;

    @Builder.Default
    private boolean enabled = true;
}

Annotation Breakdown:

@Entity
Tells JPA: "This class maps to a database table"
@Table(name = "users")
Table name in DB. Without this, it would be "user"
@Id
Marks this field as the primary key
@GeneratedValue(IDENTITY)
Auto-increment. DB generates the ID automatically
@Column(nullable=false, unique=true)
DB constraint: cannot be null, must be unique
@Builder.Default
Sets default value when using Builder pattern

Lombok Annotations on this class:

  • @Getter - Generates getId(), getUsername(), etc.
  • @Setter - Generates setId(), setUsername(), etc.
  • @NoArgsConstructor - Creates User() constructor (needed by JPA)
  • @AllArgsConstructor - Creates constructor with all fields
  • @Builder - Enables User.builder().username("x").build() pattern

This class gets mapped to a users table in PostgreSQL. JPA/Hibernate auto-creates/updates the table based on spring.jpa.hibernate.ddl-auto=update.

Repository Layer

UserRepository.java

@Repository
public interface UserRepository extends JpaRepository<User, Long> {
    Optional<User> findByUsername(String username);
    Optional<User> findByEmail(String email);
    boolean existsByUsername(String username);
    boolean existsByEmail(String email);
}

What's happening here:

  • @Repository - Marks this as a Spring-managed bean for database operations. Also translates JDBC exceptions into Spring's DataAccessException.
  • JpaRepository<User, Long> - Extends CRUD repository. You get these methods for free:
    • findAll() - SELECT * FROM users
    • findById(Long id) - SELECT * FROM users WHERE id = ?
    • save(User) - INSERT or UPDATE
    • deleteById(Long id) - DELETE FROM users WHERE id = ?
    • count(), existsById(), etc.

Spring Data JPA Magic - Query Derivation

Notice we don't write SQL! Spring Data JPA derives the query from the method name:

  • findByUsername(String username) → SELECT * FROM users WHERE username = ?
  • existsByEmail(String email) → SELECT COUNT(*) > 0 FROM users WHERE email = ?

The method name structure: [findBy|existsBy|countBy|deleteBy][Field][And|Or][Field]

Service Layer - Business Logic

UserService.java

@Service
@RequiredArgsConstructor
public class UserService {
    private final UserRepository userRepository;
    private final PasswordEncoder passwordEncoder;

    public List<User> getAllUsers() {
        return userRepository.findAll();
    }

    public Optional<User> getUserById(Long id) {
        return userRepository.findById(id);
    }

    public User createUser(User user) {
        if (userRepository.existsByUsername(user.getUsername())) {
            throw new RuntimeException("Username already exists");
        }
        if (userRepository.existsByEmail(user.getEmail())) {
            throw new RuntimeException("Email already exists");
        }
        user.setPassword(passwordEncoder.encode(user.getPassword()));
        return userRepository.save(user);
    }

    public User updateUser(Long id, User userDetails) {
        User user = userRepository.findById(id)
                .orElseThrow(() -> new RuntimeException("User not found"));
        user.setFirstName(userDetails.getFirstName());
        user.setLastName(userDetails.getLastName());
        user.setEmail(userDetails.getEmail());
        return userRepository.save(user);
    }

    public void deleteUser(Long id) {
        userRepository.deleteById(id);
    }
}

Key concepts in this class:

@Service - Marks this as a service bean. Functionally same as @Component, but semantically indicates business logic.

@RequiredArgsConstructor - Lombok generates a constructor for all final fields. Spring uses this for dependency injection (constructor injection - the recommended way).

PasswordEncoder - Injected by Spring Security's configuration. Used to hash passwords with BCrypt before saving to DB.

Method-by-method breakdown:

MethodWhat it does
getAllUsers()Returns all users from DB. Delegates to JpaRepository.findAll()
getUserById(id)Returns a single user wrapped in Optional (could be empty if not found)
createUser(user)1. Checks if username/email already exists
2. Hashes the password
3. Saves to DB
updateUser(id, details)Finds existing user, updates only firstName, lastName, email (not username/password)
deleteUser(id)Deletes user by ID

Important Pattern: Password Hashing

passwordEncoder.encode(user.getPassword()) converts "mypassword123" into something like $2a$10$N9qo8uLOickgx2ZMRZoMy...BCrypt hash. This way, even if DB is hacked, passwords are safe. Never store plain text passwords!

Controller Layer - REST API

UserController.java

@RestController
@RequestMapping("/api/users")
@RequiredArgsConstructor
public class UserController {
    private final UserService userService;

    @GetMapping
    public List<UserResponse> getAllUsers() {
        return userService.getAllUsers().stream()
                .map(UserMapper::toResponse)
                .collect(Collectors.toList());
    }

    @GetMapping("/{id}")
    public ResponseEntity<UserResponse> getUserById(@PathVariable Long id) {
        return userService.getUserById(id)
                .map(UserMapper::toResponse)
                .map(ResponseEntity::ok)
                .orElse(ResponseEntity.notFound().build());
    }

    @PostMapping
    public ResponseEntity<UserResponse> createUser(@RequestBody UserRequest request) {
        try {
            User user = UserMapper.toEntity(request);
            User savedUser = userService.createUser(user);
            return ResponseEntity.ok(UserMapper.toResponse(savedUser));
        } catch (RuntimeException e) {
            return ResponseEntity.badRequest().build();
        }
    }

    @PutMapping("/{id}")
    public ResponseEntity<UserResponse> updateUser(@PathVariable Long id, @RequestBody UserRequest request) {
        try {
            User user = UserMapper.toEntity(request);
            User updatedUser = userService.updateUser(id, user);
            return ResponseEntity.ok(UserMapper.toResponse(updatedUser));
        } catch (RuntimeException e) {
            return ResponseEntity.notFound().build();
        }
    }

    @DeleteMapping("/{id}")
    public ResponseEntity<Void> deleteUser(@PathVariable Long id) {
        userService.deleteUser(id);
        return ResponseEntity.noContent().build();
    }
}

Key concepts:

@RestController = @Controller + @ResponseBody. All methods return data directly (JSON), not view names.

@RequestMapping("/api/users") - All endpoints in this controller start with /api/users

@PathVariable - Extracts value from URL path. /api/users/5 → id = 5

@RequestBody - Deserializes the JSON request body into a Java object

ResponseEntity - Wraps the response with HTTP status code. ok() = 200, notFound() = 404, badRequest() = 400, noContent() = 204

Request-Response transformation pattern:

Client sends UserRequest
→
Mapper converts to User (Entity)
→
Service processes User (Entity)
→
Mapper converts to UserResponse
→
Client receives JSON Response

Why separate UserRequest and UserResponse DTOs?

  • UserRequest: What the client sends (includes password, no id, no enabled)
  • UserResponse: What the client receives (includes id and enabled, no password!)
  • Security: Never expose the password hash in the API response

Mapper - UserMapper Utility

UserMapper.java

public class UserMapper {
    public static User toEntity(UserRequest request) {
        return User.builder()
                .username(request.getUsername())
                .password(request.getPassword())
                .email(request.getEmail())
                .firstName(request.getFirstName())
                .lastName(request.getLastName())
                .build();
    }

    public static UserResponse toResponse(User user) {
        return UserResponse.builder()
                .id(user.getId())
                .username(user.getUsername())
                .email(user.getEmail())
                .firstName(user.getFirstName())
                .lastName(user.getLastName())
                .enabled(user.isEnabled())
                .build();
    }
}

This is a static utility class that converts between DTOs and Entity. Two methods:

  • toEntity(UserRequest) - Client JSON → Java Object (for saving)
  • toResponse(User) - Java Object → Client JSON (for returning). Note: password is intentionally excluded.

This keeps the controller clean and the conversion logic in one place.

Security Configuration

SecurityConfig.java

@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/users/**").permitAll()
                .anyRequest().authenticated()
            );
        return http.build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}

What each part does:

@Configuration - This class defines Spring beans (configuration)

@EnableWebSecurity - Enables Spring Security's web security support

csrf().disable() - Disables CSRF protection. Safe for stateless REST APIs (not browser-form apps)

requestMatchers("/api/users/**").permitAll() - Anyone can access these endpoints without login

anyRequest().authenticated() - All other endpoints require authentication

BCryptPasswordEncoder - A strong password hashing algorithm. Creates a Bean that UserService uses for password encoding.

How Spring wires it together:

SecurityConfig creates a PasswordEncoder bean → Spring finds it → injects it into UserService via constructor (@RequiredArgsConstructor). This is Dependency Injection in action!

Complete Request Flow

What happens when a client sends POST /api/users with JSON body:

Step 1 UserController.createUser() receives HTTP request
@RequestBody deserializes JSON to UserRequest object
Step 2 UserMapper.toEntity(request) converts UserRequest → User entity
Step 3 UserService.createUser(user) is called
Checks username/email uniqueness, hashes password
Step 4 UserRepository.save(user) generates and executes SQL INSERT
Step 5 PostgreSQL saves the row, returns generated ID
Step 6 UserMapper.toResponse(savedUser) converts User → UserResponse (without password)
Step 7 ResponseEntity.ok(response) sends 200 OK with JSON body

How Spring Boot Auto-Wiring Works in This Project:

1. Spring starts up
2. Finds @SpringBootApplication → scans all packages
3. Finds @Configuration classes (SecurityConfig)
4. Finds @Entity (User) → maps to DB table
5. Finds @Repository (UserRepository) → creates bean, connects to DB
6. Finds @Service (UserService) → needs UserRepository + PasswordEncoder
   → Spring injects them via constructor (@RequiredArgsConstructor)
7. Finds @RestController (UserController) → needs UserService
   → Spring injects it via constructor
8. App is ready to handle HTTP requests!
